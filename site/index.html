What it is for

    
Anything that can run a wasm module, such as a WASI runtime, an application that embeds one, or a browser, can compile Rust on the spot: no rustup, no cargo, no system linker, no C compiler and no LLVM to install.

    
    
      
  • Rust inside an application. Ship a Rust compiler with your app for user scripts, plugins or live-reloaded extensions written in Rust.
    • 
      
  • Sandboxed compile services and playgrounds. Compile in a sandbox the host controls, including in the browser.
    • 
      
  • Platforms without a native toolchain. Compile Rust where installing one is not possible or not wanted.
    • 
    


    
Priorities

    
    
      
  1. Pure Rust. The shipped compiler contains no LLVM.
    2. 
      
  2. Fast edit to result. Built for small programs.
    3. 
      
  3. Output that runs in a sandbox. With nothing but what the host chooses to provide.
    4. 
    

  


  

    
How it works

    
The compile pipeline is Rust. rustc.wasm lowers the code to Cranelift IR, clif-to-wasm turns that into relocatable wasm objects, and Wild links them on the host, because WASI has no way to start a process.

  • rustc runs as the compiler, with the rustc-to-wasm patch series and small patches of our own. Upstream: rust-lang/rust.
    • 
      
  • rustc_codegen_cranelift lowers Rust to Cranelift IR. Upstream: rust-lang/rustc_codegen_cranelift.
    • 
      
  • clif-to-wasm turns Cranelift IR into relocatable wasm object files that follow the WebAssembly C ABI. Upstream: ryancbuckley/clif-to-wasm.
    • 
      
  • Wild links the objects into a module. It is written in Rust and runs on the host. Upstream: wild-linker/wild.
    • 
      
  • Wasmtime runs the compiler and the programs it produces. Upstream: bytecodealliance/wasmtime.
    • 
    

    
Every patch is kept small and written so it can go upstream. The pinned revisions are in the experiment README.

Known limits

    
    
      
  • LLVM is still used once at build time to compile rustc itself into rustc.wasm. Nothing that ships uses it; removing it means self-hosting.
    • 
      
  • Cranelift favours compile speed, so tight numeric code is slower than LLVM -O2. The current suite numbers are in Benchmarks.
    • 
      
  • Procedural macros can't run inside rustc.wasm yet, and there is no debug info.
    • 
      
  • The first load of the 137 MB rustc.wasm on a developer machine compiles it to native code, about 38 s. Later loads use Wasmtime's cache (about 0.46 s) or a per-host .cwasm (about 19 ms, 282 MB), which is tied to the exact Wasmtime version and engine configuration.
    • 
    

  


  

    
Benchmarks

    
The suite measures compiler start, compile phases, execution against LLVM -O0 and -O2, and output size. Every result is checked bit-for-bit against both LLVM builds before a timing is accepted, so a wrong answer stops the run instead of becoming a speed-up. The quick suite runs in CI on every compiler change, and these are CI-runner numbers.

Roadmap

      Full roadmap on GitHub
    

    

      

        
Generated code as fast as LLVM

        
Close the gap on scalar code, then match LLVM's auto-vectorisation where it matters.

        
Today: tight numeric loops run about 3× slower than LLVM -O2; code that mostly calls its host runs at parity.

      

      

        
Near-instant compiler start

        
Keep the compiler resident and start it from a precompiled image instead of recompiling the module.

        
Today: 18.7 ms from a per-host .cwasm on an Apple M-series Mac; a first load without one is about 38 s.

      

      

        
The whole language and ecosystem

        
Procedural macros, std for WASI, multiple crates, components and debug info.

        
Today: procedural macros and debug info are not supported yet.

      

      

        
No LLVM anywhere, not even to build

        
Self-host rustc.wasm and remove the C library from the compiler's std.

        
Today: LLVM is used once at build time to compile rustc, and the compiler's std contains wasi-libc.

      

    

  


  

    
Contribute

    
Build and test the whole pipeline with the script CI runs:

    
ci/build-and-test.sh

    
Once that toolchain exists, the CI-sized benchmark subset is:

    
bench/run.sh --quick

    
The build requirements and the full-suite commands are in the experiment README and the benchmark README.
