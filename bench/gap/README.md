# Gap attribution tooling

This directory produces [`REPORT.md`](REPORT.md): for every benchmark, how many
wasm instructions our build executes compared with LLVM `-O2`, why, and what
the next fix should be.

```sh
bench/gap/run.sh                 # all programs, counts + analysis + MIR experiment
bench/gap/run.sh sha256 sort     # a subset
bench/gap/run.sh --no-mir        # counts and analysis only
bench/gap/build.py               # rebuild the analysed modules only
bench/gap/gc_test.sh             # Wild --gc-sections size experiment
```

`run.sh` builds `gap-tool` (Rust, pinned crates in `Cargo.lock`), builds the
suite modules through `bench/run.py`, instruments every basic block with an
exported counter, runs the suite seeds, and writes:

- `results/analysis.json` — per-program totals, per-function counts, category
  counts, cause attribution, section and function sizes. This is the raw data
  behind the report.
- `results/counts/` — per-seed block counts and static block metadata
  (git-ignored; regenerated by `run.sh`).
- `results/sizes/` — raw `gap-tool sizes` output (git-ignored).
- `results/hot/` — top-three function WAT per build, plus side-by-side
  `diff-topN.md` / `diff-inlined.md` where LLVM kept a matching body.
- `results/mir.json`, `results/MIR.md` — rustc MIR-level experiment.
- `results/SUMMARY.md` — compact tables.

The per-seed counts and the raw per-program size files are git-ignored; the
compact `results/analysis.json`, the MIR results and the hot-function WAT are
committed so the published report is readable without a rerun. The code is
split by job: `src/instrument.rs` rewrites wasm, `src/measure.rs`
runs it in Wasmtime, `src/sizes.rs` reports static bytes, and `analyze.py`
turns counts into the attribution. The instrumenter is deliberately
conservative: it re-encodes the original operator stream unchanged and inserts
only stack-neutral counter updates, so it cannot change a program's result.
